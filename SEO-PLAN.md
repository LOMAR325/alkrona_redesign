# План работ по SEO — выполнять завтра

Задача: добавить структурные SEO-элементы, **не трогая визуальный дизайн
и содержание**. Все правки — в генераторах, готовые `.html` перезаписываются.

Состояние на сегодня: сайт свёрстан (index / catalog / care), данные каталога
реальные (40 позиций), артикулы есть у всех 40, латинские названия у 38,
описания длиннее 200 символов у всех 40. Цены известны только у 4 позиций.

---

## Решения, принятые заранее (не переобсуждать)

**1. URL повторяют структуру живого сайта.** На alkrona.by уже проиндексированы
`/catalog/`, `/about/`, `/delivery/`, `/product/<slug>/`. Новые страницы кладём
по тем же адресам — тогда при запуске не нужны 301-редиректы и не теряются
накопленные сигналы. Итоговая карта:

| URL | Файл | Что это |
| --- | --- | --- |
| `/` | `index.html` | Главная |
| `/catalog/` | `catalog/index.html` | Весь каталог |
| `/catalog/hvojnye/` | `catalog/hvojnye/index.html` | Категория «Хвойные» |
| `/catalog/listvennye/` | `catalog/listvennye/index.html` | Категория «Лиственные» |
| `/product/<slug>/` | `product/<slug>/index.html` | 40 страниц товаров |
| `/delivery/` | `delivery/index.html` | Доставка и оплата |
| `/opt/` | `opt/index.html` | Опт и ландшафтным компаниям |
| `/contacts/` | `contacts/index.html` | Контакты |
| `/care/` | `care/index.html` | Посадка и уход (сейчас `care.html`) |
| `/about/` | `about/index.html` | О питомнике |

Старые плоские файлы (`catalog.html`, `care.html`) оставить как редирект-заглушки
или удалить — решить в конце, когда будет ясно, куда ведут внутренние ссылки.

**2. Категории — отдельные статические страницы, а не `?cat=`.**
Так канонический адрес прописывается статически, а вводный текст решает проблему
thin content. Query-параметры (`?sort=`, `?cat=`) остаются рабочими для
фильтрации внутри `/catalog/`, но канонизируются на чистый `/catalog/`.

**3. Цены не выдумывать.** У 36 позиций цены нет. В `Product` JSON-LD для них
`offers` не указываем вовсе (товар останется валидным, просто без ценового
rich-сниппета). Указывать «0» или придуманную цену — прямой путь к санкциям.
`availability` у всех — `InStock` (в данных `inStock: true` у всех 40);
«Цена по запросу» относится к цене, а не к наличию.

## Шаг 1. Каркас: поддержка вложенных URL в `tools/build.py`

Сейчас `head()`, `header()`, `footer()` зашивают относительные пути
(`assets/...`, `index.html`). Для страниц в подпапках нужен префикс.

- [ ] Добавить параметр `base` (`""`, `"../"`, `"../../"`) в `head`, `header`,
      `footer`, `DIALOGS`, `SCRIPTS`; подставлять его во все `assets/...`
      и внутренние ссылки.
- [ ] `NAV` переписать на абсолютные пути от корня (`/catalog/`, `/care/`,
      `/delivery/`) — тогда префиксы не нужны в меню вовсе. **Это проще:
      сделать так, а `base` оставить только для `assets/`.**
- [ ] В `assets/js/app.js` пути к фото строятся в `img()` как
      `'assets/img/plants/' + name`. Добавить `ALK.base` (задаётся инлайн-скриптом
      в `head()` до подключения `app.js`) и использовать его в `img()`,
      в `paintReq()` и в модалке. Иначе на страницах в подпапках отвалятся
      все картинки, собираемые JS.
- [ ] Проверка `check_assets()` в конце `build.py` должна учитывать префиксы —
      иначе она начнёт ложно ругаться.

## Шаг 2. Общие мета-теги

В `head()` добавить параметры `canonical`, `og_image`, `og_type`:

- [ ] `<link rel="canonical" href="https://alkrona.by/...">` на каждой странице.
- [ ] `og:url`, `og:image`, `og:image:width/height`, `og:image:alt`.
- [ ] `twitter:card = summary_large_image` + `twitter:title/description/image`.
- [ ] Картинка для превью: сделать `assets/img/og/og-default.jpg` 1200×630
      из `field-3894` (реальное поле, не генерация — важно). Добавить в
      `tools/fetch-assets.py` отдельный вызов `save(..., ratio=1200/630)`.
      Для страниц товаров — `og:image` = фото товара 800×800 (допустимо,
      Telegram/VK покажут квадрат).
- [ ] Логотип в шапке: сейчас `alt=""`. Заказчик просил
      `alt="Алькрона — питомник растений"`. **Сделать, но помнить:** рядом
      лежит видимый текст «Алькрона / питомник растений», и скринридер
      прочитает название дважды. Если важнее доступность — оставить `alt=""`.
      Спросить заказчика, по умолчанию делаем как просил.

## Шаг 4. JSON-LD

Новый модуль `tools/schema.py`, функции возвращают `<script type="application/ld+json">`.

- [ ] `local_business()` — тип `GardenStore` (валидный подтип Store; `GardenCenter`
      в schema.org **нет**, проверить перед вставкой). Поля: `name`, `url`, `logo`,
      `image`, `telephone: +375293191844`, `email`, `priceRange: "₽₽"` →
      лучше `"10–210 BYN"`, `address` (`streetAddress`: микрорайон «Свислочь
      Новая»; `addressLocality`: Свислочь; `addressRegion`: Минская область;
      `postalCode`: 220823 — **сверить, у Свислочи Пуховичского района 222823**;
      `addressCountry`: BY), `geo` (53.6455, 27.9158),
      `openingHoursSpecification` (Mo–Sa 09:00–17:00).
      Ставить на все страницы.
- [ ] `breadcrumbs(items)` — `BreadcrumbList` там, где крошки видны:
      каталог, категории, товары, разделы. На главной крошек нет — не ставить.
- [ ] `product(p)` — `name`, `image` (полный URL), `description` (первые
      ~300 симв. из `desc`), `sku`, `brand: Алькрона`,
      `additionalProperty` для горшка и высоты; `offers` только при `price > 0`
      (`priceCurrency: BYN`, `availability: InStock`, `url`, `seller`).
- [ ] `item_list()` на `/catalog/` — `ItemList` со ссылками на 40 товаров.
- [ ] Проверить всё в валидаторе schema.org и Rich Results Test **до** запуска.

## Шаг 5. Страницы товаров (40 шт.)

## Чего не делать

- Не менять визуальный дизайн, палитру, шрифты и композицию секций.
- Не переписывать тексты, которые уже согласованы, ради ключевых слов.
- Не добавлять цены, которых нет в данных.
- Не плодить страницы под запросы без реального содержания.
