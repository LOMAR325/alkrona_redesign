# Алькрона — сайт питомника декоративных растений

Редизайн сайта [alkrona.by](https://alkrona.by): питомник в г.п. Свислочь Минской
области, собственное выращивание хвойных и лиственных декоративных кустарников.

Светлая, спокойная тема — зелёные и песочные тона, крупная фотография, чистая
типографика. Статический сайт: HTML, CSS и обычный JavaScript, без сборщиков,
фреймворков и зависимостей.

```bash
python3 serve.py
```

Откроется на <http://127.0.0.1:4173>. Файлы можно открыть и напрямую из
файловой системы — всё работает без сервера.

## Структура

```
index.html            Главная: хиро, «что растёт», лента каталога, аудитории,
                      полоса «о питомнике», как купить, уход, галерея, контакты
catalog.html          Каталог с фильтрами, поиском и сортировкой
care.html             Развёрнутые рекомендации по посадке и уходу
assets/css/           Одна таблица стилей, токены — в начале файла
assets/js/            app.js (вся логика) + catalog-data.js (данные каталога)
assets/data/          catalog.json — те же данные в JSON
assets/img/plants/    Фотографии товаров, WebP 400 и 800 px, единый грейд
assets/img/nursery/   Фотографии питомника, WebP: квадрат, 1600, широкий 16:9
tools/build.py        Сборка HTML-страниц + проверка, что все файлы на месте
tools/icons.py        Свой набор иконок (ветка, лист, горшок, шишка, лейка…)
tools/fetch-assets.py Импорт каталога и фотографий с alkrona.by + цветокоррекция
serve.py              Локальный сервер для предпросмотра
archive/              Первый, отклонённый концепт (тёмная тема) — не используется
```

## Как править

**Разметку страниц** — в `tools/build.py`, затем:

```bash
python3 tools/build.py
```

Шапка, подвал, меню и диалоги описаны там один раз и подставляются во все три
страницы. Сборка заодно проверяет, что каждая картинка со страниц существует
на диске, и ругается, если ссылка ведёт в пустоту. Готовые `.html`
перезаписываются — руками их править не нужно.

**Иконки** — в `tools/icons.py`. Все рисуются одной линией в 24×24 и красятся
`currentColor`, поэтому цвет и толщина задаются в CSS по месту.

**Каталог** — данные в `assets/js/catalog-data.js`. Обновить с живого сайта
вместе с фотографиями:

```bash
python3 tools/fetch-assets.py              # каталог + фото питомника
python3 tools/fetch-assets.py --plants-only # только каталог, быстрее
```

Скрипт читает публичный API WooCommerce, скачивает фото, прогоняет их через
единый грейд (баланс белого, уровни, насыщенность, тёплый оттенок, мягкое
виньетирование) и пересобирает `catalog.json` и `catalog-data.js`.

**Цвета и типографику** — переменные в начале `assets/css/styles.css`.

## Оформление

**Шрифты.** Заголовки — **Literata**, переменный шрифт с осью оптического
размера: крупные заголовки набираются начертанием для больших кеглей
(`opsz 60–72`) с плотным трекингом, мелкие — начертанием для текста (`opsz 14–28`),
поэтому засечки не выглядят «растянутым Georgia». Текст и интерфейс —
**Golos Text**, кириллический гуманистический гротеск.

Заголовки разного веса по смыслу, а не одним размером: `.t-hero` (хиро),
`.t-major` (ключевые секции), `h2`, `.t-minor` (карточки и блоки).

**Палитра.** Зелень питомника `#2f6b45`, тёплая бумага `#faf7f0` и песок
`#f2ebdd`, плюс два акцента из осенней листвы с самого участка: терракота
`#ad5334` (иконки, ховеры, «Под заказ», акценты в цифрах) и охра `#b5842f`
(плашка «Хвойное», подсветка в тёмных блоках). Весь текст проходит
по контрасту не ниже 4.5:1.

**Фактура.** Едва заметное зерно бумаги поверх фона, мягкие градиенты
и виньетирование на фотографиях, тёплый белый `#fffdf8` у карточек вместо
чистого белого.

**Тени трёх весов**: `--sh-card` для карточек товара, `--sh-panel` для
инфоблоков, `--sh-lift` для формы, модалки и выносных карточек.

**Формы кнопок** тоже с иерархией: основное действие — прямоугольная кнопка
с радиусом 11px, «таблеточный» радиус остался только за второстепенными
кнопками, чипами и плашками.

**Композиция секций** намеренно разная: асимметричный сплит с крупным фото,
горизонтальная лента каталога, полоса во всю ширину с наложенным текстом,
таймлайн, карточки со сдвигом по вертикали. Вместо повторяющегося «тире +
капслок» — крупные порядковые номера и метки с ботанической иконкой.

## Что умеет каталог

- Фильтры: тип растения, высота, размер горшка (Р9…С10 и ОКС), цена, наличие.
  Счётчики у каждого пункта пересчитываются с учётом остальных фильтров
- Поиск по названию, латинскому названию, артикулу и описанию
- Сортировка: наличие, название, цена, высота
- Состояние фильтров пишется в адрес страницы — ссылку можно переслать
  (`catalog.html?cat=hvojnye-derevya-i-kustarniki`)
- Карточка растения: фото с галереей, артикул, тип, размер горшка, высота,
  наличие, цена, описание
- «Заявка» — список выбранных растений в `localStorage`; на странице контактов
  он сам подставляется в форму с артикулами и количеством

## Производительность и доступность

- Все фотографии в WebP, миниатюры карточек ≈25–45 КБ
- `loading="lazy"` и явные `width`/`height` у всех изображений — нет скачков вёрстки
- Ссылки на CSS и JS содержат метку версии по времени файла — при обновлении
  сайта у посетителей не останется старый кэш
- Контраст всего текста — не ниже 4.5:1 (проверено)
- Формы с подписями, диалоги закрываются по Esc, есть поддержка
  `prefers-reduced-motion` и `prefers-contrast: more`

## Что нужно доделать перед публикацией

### 1. Формы никуда не отправляются

Форма заявки показывает подтверждение, но письмо не уходит. Нужно подключить
обработчик на сервере или сервис форм — точка входа в `assets/js/app.js`,
функция `initForms()`. (Предупреждающая подпись под формой убрана со страницы,
чтобы не смущать посетителей, — но подключить отправку всё ещё нужно.)

в углу. Я их не подменял и водяные знаки не убирал: для питомника это вопрос

### 3. Цены заполнены только у 4 товаров из 40

У остальных в WooCommerce цена `0`, поэтому на сайте выводится «Цена по запросу»,
а в фильтре цены есть отдельный пункт. Если цены известны — их стоит внести
в товары, фильтр и сортировка подхватят автоматически.

### 4. Ошибка в данных

У «Сосны горной „Мугус“» латинское название указано `Juniperus sabina` — это
можжевельник казацкий. Должно быть `Pinus mugo`. Стоит проверить и остальные
латинские названия.

### 5. Истёк SSL-сертификат alkrona.by

Браузеры показывают предупреждение об опасности сайта. Для питомника, который
работает с ландшафтными компаниями и застройщиками, это бьёт по доверию сильнее
любого дизайна. Чинится бесплатно через Let's Encrypt.

### 6. Схема проезда — своя, не виджет

Встроенная карта OpenStreetMap показывала в своём интерфейсе служебные ссылки
(«Сделать пожертвование», «Условия сайта и API»), которые выглядели как остатки
конструктора. Вместо неё нарисована своя схема: Минск, дорога, расстояние
и точка питомника, плюс кнопка «Открыть в картах» на Яндекс.Карты. Схема
не масштабная — если нужен точный маршрут, лучше добавить ссылку на готовую
точку в Яндекс.Картах с координатами 53.6455, 27.9158.

### 7. Мелочи

- Индекс: на сайте указан `220823`, у г.п. Свислочь Пуховичского района — `222823`
- Атрибут «Горшок» WooCommerce режет по запятой, поэтому «С1,5» хранится как два
  значения. При импорте это чинится, но лучше поправить в самой WooCommerce
- Год основания питомника нигде не указан — в хиро его нет, хотя для доверия
  строка «выращиваем с … года» работает хорошо
